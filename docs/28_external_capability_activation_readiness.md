# 28 外部制約・機能有効化準備仕様

更新日: 2026-08-26

## 1. 目的

本書は、現在の無料プラン、未採用データ、利用規約、契約、認証、履歴不足等によって制限されている機能について、制約が解消された時に調査をやり直さず、安全に実装を開始するための正本である。

有料プランの契約、APIキーの発行、データ提供開始は、実装・有効化の自動承認ではない。外部条件が変わった場合も、公式条件確認、利用者承認、Macでの隔離検証、品質ゲート、現在判断の前向き観察、Raspberry Pi配置承認を順番に満たす。

本書は`docs/22_current_priority_todo.md`の実装順を置き換えない。条件がそろった機能は、同文書へ実装タスクを追加または既存タスクと統合してから着手する。

## 2. 状態

外部能力ごとに次の状態を管理する。

| 状態 | 意味 |
| --- | --- |
| `blocked_external` | 契約、権利、必要データ、認証、履歴等が不足している |
| `candidate_available` | 利用可能になった可能性があり、公式確認を開始できる |
| `approved_for_design` | 費用・用途・規約を利用者が承認し、設計を開始できる |
| `ready_for_mac_validation` | 認証と最小応答が確認でき、Macの隔離環境で実装・検証できる |
| `approved_for_current_market` | 鮮度、時点整合、品質、表示のゲートを満たし、利用者が現在判断の前向き記録を承認した |
| `approved_for_raspberry_pi` | バックアップ、停止影響、単一実行主体、ロールバックを提示し、利用者が配置を承認した |
| `active` | 承認済み範囲で稼働中 |
| `suspended` | 契約切れ、規約変更、品質低下、障害等により停止中 |

プラン変更だけで`blocked_external`から`active`へ移行しない。料金プランに複数の機能が含まれていても、価格、指数、財務、信用、分足等を能力単位で個別に判定する。

## 3. 実装開始前に必要な共通情報

次の情報がそろった能力だけを`approved_for_design`以降へ進める。

1. provider、商品、料金プラン、アドオンの正確な名称と契約開始・更新・終了条件
2. 利用者による費用と対象機能の明示承認
3. 公式のエンドポイント、項目、データ遅延、更新頻度、履歴範囲
4. 調整済み／未調整価格、企業行動、改訂、タイムゾーン、セッション日の意味
5. レート制限、日次・月次クォータ、429時の扱い、同時実行条件
6. 私的利用、保存、バックアップ、派生値、画面表示、再配布に関する利用規約
7. 認証方式と秘密情報の保存場所。秘密値そのものは本書、Git、ログへ保存しない
8. Python 3.12、Apple Silicon、Raspberry Pi ARM64での利用可否
9. サンプル応答または少数銘柄・短期間の実応答と、NULL・エラー応答の例
10. 解約、契約切れ、クォータ超過、障害時の縮退運転とロールバック方法

公式条件の確認日、URL、判断結果は`docs/data_sources.md`へ記録する。APIキーの有無は真偽値として記録できるが、キー、パスフレーズ、口座情報は記録しない。

## 4. J-Quants Freeから上位プランへ移行できる場合

現在のFree運用は、日本株・日本ETFの日次価格が約12週間遅延するため`delayed_historical`専用である。上位プランを利用できるようになった場合は、次を能力別に確認する。

| 能力 | 現在の制約 | 実装開始に必要なもの | 有効化前の追加条件 |
| --- | --- | --- | --- |
| 日本株・日本ETFの現在に近い日次OHLCV | Freeは約12週間遅延 | 正確なプラン名、対象資産、遅延、履歴、調整仕様、クォータ、利用承認、少数銘柄の実応答 | 全対象の鮮度監視、`available_at`、欠損・改訂・分割検証、Mac前向きシャドー |
| TOPIX・指数OHLC | Freeでは必要範囲を取得できない | 対象指数、四本値／終値、履歴、更新時刻、利用承認 | 既存FRED系列とのsource分離と比較、欠損時の暗黙代用禁止 |
| 財務情報 | Free公開範囲では対象外 | 対象項目、開示時刻、改訂履歴、利用承認 | `available_at`基準の先読み防止、訂正開示の版管理 |
| 信用残・空売り・貸借関連 | プランと提供範囲が未確定 | 項目、更新頻度、履歴、市場範囲、規約、利用承認 | 証券会社固有在庫・費用と混同せず、取得不能値をゼロにしない |
| 分足・ティック・前場四本値 | 有料またはアドオンの可能性 | 本機能が本当に必要なユースケース、容量、クォータ、費用、利用承認 | 時刻精度、取引停止、重複、保存容量、Raspberry Pi負荷の実測 |
| 銘柄・企業行動・ライフサイクル | 過去時点の完全性が不足 | 過去スナップショット範囲、上場・廃止・分割等の項目、改訂仕様 | 既存履歴を上書きせず、時点別完全性を証明できること |

上位プランに変更しても、Freeで取得済みの価格や既存分析を上書きしない。`source`、provider版、取得時刻、利用可能時刻を分離し、同一時点で比較できる形で追加する。過去データを後から埋めても、正式な前向き観察期間へ遡って算入しない。

信用取引についてはMT-P0で交換可能な`MarginTradingProvider`、日米正規化型、4モード、欠損・鮮度・先読み防止境界を実装済みである。MT-P1では適格性、市場残高、費用・保証金を分けた追記型DBと時点読出しも実装済みである。契約後は既存型やDBを変更してAPIへ密結合せず、最初に公式応答adapterとfixtureを追加する。提供されない項目はNULLのまま保持し、`broker_scope`、`source_version`、`effective_from`、`available_at`、`fetched_at`、品質状態を埋められない能力は有効化しない。

J-Quantsの契約変更を利用者から知らされた場合、最初に確認するのは、正確なプラン名、利用開始日、利用したい能力、公式プラン・API資料、APIキーの権限変更有無、更新・失効日である。秘密値の提示は求めない。

## 6. 実装から本番有効化までの順序

1. **能力監査**: 公式資料で第3節を埋め、既存要件との差分を報告する。
2. **利用者承認**: 費用、更新、対象能力、規約、保存範囲を提示し、導入承認を得る。
3. **交換可能な境界**: provider interface、型、fixture、正常・欠損・429・認証失敗テストをMacで実装する。
4. **隔離検証**: 少数銘柄・短期間を隔離DBまたは書き込みなしで取得し、秘密のマスキング、再試行、冪等性を確認する。
5. **時点整合検証**: `effective_at`、`available_at`、`fetched_at`、source、revision、qualityを保存し、既存sourceとの不一致を可視化する。
6. **制御されたバックフィル**: 保存量とAPI負荷を見積もり、小さい範囲から拡大する。後付けデータを前向き成績へ入れない。
7. **Mac前向きシャドー**: 凍結後の新しい取引セッションだけを追記し、`delayed_historical`と混在させない。候補なし・障害日も記録する。
8. **現在判断の承認**: 品質ゲート結果と既知の制約を提示し、利用者承認後だけ`current_market`表示・記録を有効化する。
9. **Raspberry Pi配置の承認**: バックアップ、マイグレーション、停止影響、単一実行主体、容量、ロールバックを提示して別途承認を得る。
10. **継続評価**: 6〜12か月程度の前向き観察、十分な標本、独立未見検証を行う。データが新しくなっただけで実投資支援能力や予測性能が証明されたとは扱わない。

## 7. 昇格を禁止する条件

- 古い価格と最新ニュース、現在為替、現在金利を同一判断へ混在させる。
- 契約プラン名や利用権限を推測する。
- 欠損、取得不能、信用在庫不明、費用不明をゼロまたは利用可能として補完する。
- 新providerの値で既存sourceの行、過去判断、凍結済み戦略を上書きする。
- API障害時にJ-Quants Free等の遅延sourceへ黙って切り替え、`current_market`を継続する。
- バックフィルを正式な前向き観察として数える。
- Macで未検証のマイグレーションや常駐ジョブをRaspberry Piへ直接配置する。
- 有料契約や新しいAPIキーだけを理由に品質ゲート、利用者承認、前向き検証を省略する。

## 8. 記録項目

外部能力の採用記録には、少なくとも次を残す。

- `capability_id`
- provider、正確なplan／product／add-on
- status、対象機能、対象市場・資産
- `approved_at`、`effective_at`、`expires_at`、`official_checked_at`
- 公式URL、endpoint、field coverage、latency、history、quota
- 保存・表示・派生値・再配布条件
- credentialの設定有無。秘密値は保存しない
- Macテスト、品質ゲート、比較結果、入力ハッシュ
- `current_market`承認、Raspberry Pi承認
- 障害時動作、解約時動作、rollback
- 未解消制約と次の確認日

## 9. 本書の適用範囲

本書は、外部サービスの採用、契約、コード変更、DB変更、`current_market`の有効化、Raspberry Pi配置を承認するものではない。現行の実装順と次タスクは`docs/22_current_priority_todo.md`だけを正本とする。
