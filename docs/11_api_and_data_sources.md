# 11 API・データソース方針

## 原則
- 無料または無料枠を優先
- 公式・信頼できるデータを優先
- 利用規約、再配布条件、レート制限を確認
- スクレイピングは規約と安定性を確認し、安易に採用しない
- プロバイダーを交換可能にする
- 外部制約が解消した場合の実装開始・Mac検証・現在判断・Raspberry Pi配置の昇格条件は`docs/28_external_capability_activation_readiness.md`を正本とする
- 有料契約やAPIキー発行だけで、遅延研究データを`current_market`へ昇格させない

## 候補
- J-Quants: 日本株・財務・取引日等（契約・無料枠の最新条件を実装時に確認）
- FRED: 金利・マクロ
- Alpha Vantage: 株価等
- Finnhub: 株価・企業イベント等
- SEC EDGAR: 米国企業開示
- その他、利用規約上問題のないデータ源

## 信用取引データ

信用買い・信用売りの本番評価には、取引可否、制度／一般信用または市場固有区分、貸借・在庫、信用残、貸借倍率、逆日歩・借株コスト、信用金利・貸株料、返済期限、保証金・維持率等の時点整合データが必要である。

- J-Quantsの信用取引関連データはプランごとの提供範囲、履歴、更新時刻、利用規約を公式情報で再確認する。
- 証券会社固有の一般信用在庫、金利、貸株料、保証金条件等は交換可能なprovider候補とし、規約と自動取得可否を確認する。
- 米国資産はmargin eligibility、short availability、borrow fee、maintenance requirement等を候補とし、日本固有制度を推測適用しない。
- 有料プラン、有料API、証券会社接続は、費用・規約・保存可能範囲を提示してユーザー承認を得るまで採用・有効化しない。
- 取得できない値をゼロ、在庫あり、信用取引可能として補完しない。過去時点の可否・費用を復元できない期間は実データの信用バックテスト対象外にする。

## テーマ・セクターETFデータ

詳細要件は`docs/27_theme_sector_etf.md`、採用状態は`docs/data_sources.md`を正本とする。

- JPX公式ETF一覧・銘柄別資料はコード、名称、対象指数、売買単位、上場日の照合に使うが、現在の流動性や信用取引可能性の証明には使わない。
- テーマごとに米国先行資産、商品、為替、金利、構成銘柄、資金フロー、ニュース・イベントのproviderを交換可能にする。
- Bid/Ask、板、NAV、純資産、ファンドフロー、証券会社別信用条件は未採用であり、無料枠、規約、保存・表示権、更新頻度を提示してユーザー承認を得る。
- SBI証券、楽天証券等の条件は認証不要の公開情報、利用者の明示入力、または承認済みproviderに限定し、ログイン・ブラウザ自動取得・注文を行わない。
- 各値に`effective_at`、`available_at`、`fetched_at`、source、revision、quality、権利情報を持たせ、最新ニュースを遅延価格へ混ぜない。

## 取引カレンダー（P0-3後続）

- JPXの公式「Market Holidays」を日本市場の休場日確認の正本とする。休場日は将来変更され得るため、実装・更新時に公式ページを再確認する。
- NYSEの公式「Holidays & Trading Hours」を米国市場の休場日・夏時間確認の正本とする。早期終了日は日次終値分析の休場とは区別して記録する。
- 実行時のセッション判定には、Apache-2.0ライセンスのPythonライブラリ`exchange_calendars`を用いる候補とする。MacとPython 3.12コンテナで東京`XTKS`とNYSE`XNYS`を確認済み。公式カレンダーとの差異、臨時休場、将来年の更新範囲は公式情報で検証し、差異がある期間は分析から除外する。
- このライブラリはカレンダー計算用であり、価格データの取得元・来歴を置き換えない。
