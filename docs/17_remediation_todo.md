  - 日付全体の休場判定を単一銘柄に依存しない。
  - 完了条件: エラー分類・再試行・進捗再開のテストが通る。

  優先度引上げ: 2026-07-12のRaspberry Pi読み取り確認で、J-Quantsの429が`unavailable`として蓄積していることを確認した。以後のデータ損失を防ぐため、P0-3より先に実装・Mac検証する。

  完了: Mac側テストと、2026-07-12のRaspberry Pi配置・実運用確認を完了。null価格のHTTP 200応答は個別銘柄の`no_data`として保存され、日付全体は除外されないことを確認した。429・5xxは単体テストで`retry_pending`へ分離済みであり、実ログは継続監視する。

- [ ] **P1-2 J-Quantsの期間取得方式を再設計する**
  - 公式のFree plan条件、期間指定上限、ページング、レート制限を実装直前に再確認する。
  - 現行の「1銘柄×1日」方式の実測を基準に、「1銘柄×期間」方式を比較・採用判断する。
  - 最新日を全銘柄で埋めた後は、未取得日を古い順に補完する。

  実装済み: 全銘柄の最新取得可能日を候補リストの先頭に固定し、その完了後は履歴日を古い順に補完する順序へMac側で修正した。J-Quantsのページングキーを追跡する期間取得基盤も追加した。Macで86970・2026-04-01〜2026-04-10を1回実測し、8行・433msだった。現行の1銘柄×1日方式は4,448銘柄を4件/分で約18.5時間が目安だが、期間方式の全期間ページング回数と429率は追加実測が必要。
