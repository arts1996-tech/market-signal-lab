# 22 現行の最優先開発ToDo

本書は現行の実装順、未完了項目、完了状態を管理する唯一の正本である。安定した要件は各仕様書、詳細な作業証跡はGit履歴、実行時の件数・容量・障害はDBと運用画面へ残す。

## 1. 更新ルール

- 項目の完了には、コード、対象テスト、全pytest、必要な画面またはジョブ確認、文書、既知の制約を含める。
- Raspberry Piの配置、DB、cron／timerを変える場合はMac検証後に利用者承認を得る。
- 通常／デモ、`delayed_historical`／`current_market`を混在させない。
- 過去文書や機能仕様に残る「次の作業」より本書を優先する。
- 完了時はチェック状態と短い結果だけを更新し、テスト件数、バックアップ名、DB件数の日誌を蓄積しない。

## 2. 現在の順序

1. `TH-P1`のETF資産照合（外部データ待ち）
2. `MT-P3`から信用ポジション・約定
3. 依存が完成した`KN-P`、`LITE-P`を接続
4. `NOW-P2-6`以降のセキュリティ・運用強化

前向き口座と監査は並行監視し、欠測・改変・連続失敗があれば新機能より先に是正する。現在価格、ニュース、LLM、正式な`current_market`は外部データ品質ゲートを迂回して有効化しない。
