# 12 受け入れ基準

## 共通
- Mac Apple SiliconとRaspberry Pi ARM64を想定
- `.env.example` がある
- 秘密情報がGitに含まれない
- `docker compose up -d --build` で起動可能
- READMEに起動・停止・ログ・テスト・バックアップ手順
- pytestが通る
- エラーが利用者に分かる
- データ時点と取得元を表示
- 新しいproviderまたは上位プランは、正確な商品名、対象能力、料金、規約、保存・表示権、遅延、履歴、クォータ、失効時動作を公式確認し、利用者承認を記録する
- 新sourceはMac隔離環境で正常、欠損、429、認証失敗、改訂、冪等性、秘密マスキングを検証し、既存sourceと時点・版を分離する
- `current_market`は鮮度・時点整合・品質ゲートとMac前向きシャドーを通過し、利用者が明示承認した場合だけ有効化する
- Raspberry Piへの外部provider配置は、バックアップ、容量、単一実行主体、ロールバックを確認し、別途承認を得る

## フェーズ1
- DBマイグレーションが成功
- 資産と日次OHLCVを保存可能
- 重複登録しない
- 米国市場セッションと次の日本営業日を対応可能
- 基本リターンと相関を計算
- Streamlitで指数比較と相関を表示
- 欠損・古いデータを警告

## フェーズ2
- ギャップ、場中、日次を分離
- 条件別統計にサンプル数を表示
- 休日・夏時間テスト
- 先読みなしのウォークフォワード検証
- 相関と因果を混同しない説明

## フェーズ3
- 東証カレンダー上で連続する30営業日以上の、重複しない有効な調整済み価格だけを短期スクリーニング対象にする
- 年単位の空白や未取得セッションをまたいで5日・20日騰落率を計算しない
- 観測数、データ時点、価格基準、取得元を確認できる
- 20日指標は30営業日ゲート後に利用し、50日・75日移動平均は各必要観測数がそろった場合だけ利用する
- Slow Stochastic 14-3-3は連続した有効OHLCだけで計算し、欠損・不整合・値幅ゼロを補完しない。Raw %K、Slow %K、%D、計算版を保存・表示する
- 支持・抵抗候補は分析時点までに確認済みの局所高値・安値だけから、価格帯、接触数、最終接触日、無効化価格・条件を保存・表示する。直近30営業日の連続した有効OHLCが不足する場合は未算出とし、候補を注目度・変動候補スコアへ自動加点しない
- ブレイクアウトは過去20営業日の終値高値、同時点の出来高比率・寄付きギャップ・売買代金を連続した有効OHLCVから保存・表示する。出来高・寄付き・履歴の不足を補完せず、後続5観測による`failed`／`held`評価は発生時点のスコアへ遡及反映しない
- 分析候補には決定論的な注目度、根拠、品質警告を表示し、上昇確率・売買推奨と誤認させない
- J-Quants Free planの遅延をスクリーニング画面で明示する
- 財務・ETF固有指標の未取得値を推測しない
- スクリーニングを投資推奨として表示しない
- 信用買い・信用売り可否、信用区分、貸借区分、信用残、貸借倍率、逆日歩、借株・金利・貸株料、返済期限、保証金条件をprovider境界から時点付きで保存できる
- 日本と米国の制度差を明示的に正規化し、該当しない制度値や取得不能値を推測しない
- 信用データの取得元、対象市場・証券会社、`effective_at`、`available_at`、`fetched_at`、品質状態を確認できる
- テーマ、基準Tier、関連ETF・個別株、説明変数、流動性規則をコード変更なしに新版追加できる
- テーマ別モデルの各構成要素、重み、coverage、必須欠損、入力ハッシュ、モデル版から0〜100研究スコアを再現できる
- 基準Tier、日次順位、Tier変更提案を分離し、変更を過去の分析・検証へ遡及適用しない
- 銀価格と銀関連企業、銅価格と銅関連企業、半導体とAIインフラ、防衛と宇宙の重複・相関・集中を識別できる
- 新規ETF、流動性不足、板・NAV・純資産欠損を推測せず、短期候補を警告・抑制・禁止できる
- 遅延テーマランキングと現在テーマランキングを別系列にし、最新ニュースを遅延価格へ混ぜない
- SBI証券、楽天証券等の条件をbroker別・時点付きで分離し、認証情報、注文機能、ブラウザ自動操作を持たない

## フェーズ4

- 終値を含む情報で判断した取引は、同じ終値で約定させず、判断後の次取引可能セッションで約定する
- シグナル時点、判断時点、エントリー日、決済日、使用価格、約定規則を確認できる
- 始値等の必要な約定価格が欠損している場合は、終値等を暗黙補完せず取引を見送る
- 空売り固有の費用と制約が完成するまで、下方向シグナルを空売り利益として計上しない
- エントリー時に現金を拘束し、同じ資金の重複使用、保有上限超過、同日引け資金の同日寄付きへの遡及利用を防ぐ
- 手数料、スプレッド、税引前／税引後の評価基準、税モデル版、売買単位、同時保有上限、1銘柄上限を明示する。現行版は税率0%の税引前評価とし、口座種別・源泉徴収・損益通算等を再現したと表示しない
- 仮想成績は候補スコアへ自動反映せず、十分な標本と較正方法の承認後に別途検討する
- 総損益、最大ドローダウン、完了取引数、勝率、平均取引損益、同期間ベンチマークとの差を表示する
- 勝率と平均取引損益は標本数と95%近似区間を併記し、少数標本を確定的な成績として扱わない
- 前営業日出来高だけを使う参加率上限、部分約定、値幅制限フラグ、取引停止、窓開け、同日中の利益確定・損切り同時到達を保守的に処理する
- 戦略版、約定版、入力データ版、入力ハッシュ、監査ID、判断カードを確認できる
- 業種集中上限、口座ドローダウン停止、連続損失後のクールダウンをテストする
- 許容損失額とエントリー・損切り価格差から参考数量を逆算し、全保有の計画損失上限を超えない
- 分割・併合・現金配当は未調整価格と確認済み企業行動だけで反映し、合併・株式交換、端株現金化、外貨配当、確認期間不足、為替、実データで取得できない値幅制限等は警告または評価保留にする
- 上場日・上場廃止日・時点別市場／業種／投資可能状態と完全性を分離保存し、過去時点の完全な銘柄集合を復元する。現存銘柄だけで検証せず、明示上場廃止または完全な次回集合からの消失は版管理した保守的回収規則で処理する
- USD資産はUSD建て金額、JPY換算損益、銘柄価格寄与、USD/JPY寄与、取引時・評価時レート、為替スプレッド・換算コストを分離記録する。同時点の利用可能レートがなければ前方補完せず約定・評価を保留する
- 学習期間と未使用検証期間を分離し、前向き仮想運用が完了するまで実投資判断に使用しない
- 異なるルールによる同一検証期間の再利用を拒否し、同一ルールの再実行は冪等に扱う
- 学習・検証入力と凍結ルールのハッシュを保存し、不完全な検証窓と凍結時点ですでに観測済みの端数期間を前向き成績へ含めない
- 前向き開始日を凍結時点の最終観測営業日より後へ固定し、その後の観測を過去検証へ戻さない
- 決済済み取引を判断日時点の相場方向、ボラティリティ、為替、業種、流動性、スコア帯で版付き分類し、将来の指数・為替や欠損補完を使わない
- 区分別に標本数、勝率・平均取引損益率の95%区間を表示し、30件未満を成績判定しない
- 判断カードのエントリー、約定見送り、決済を同じカードIDの時系列イベントとして追跡できる
- 前営業日売買代金帯の代理コスト、最低売買代金、保有銘柄間相関上限を明示し、将来データを使わない
- 日次前向き記録は非営業日を除外し、同じ営業日の結果を後発入力で置換せず、候補なしの日も監査できる
- 判断カードと仮想口座で`cash`、`margin_long`、`margin_short`、`auto_select`を識別し、`auto_select`は採用モードと全却下理由を保存・表示する
- 信用買いは上昇トレンド、出来高、支持線、ATR、市場環境、信用買い残過熱、貸借倍率、決算、必要保証金、想定損失、信用金利を評価する
- 信用売りは下落トレンド、戻り売り、抵抗線、出来高、市場環境、信用売り残、踏み上げ、逆日歩・借株コスト、流動性、決算を評価する
- 信用取引の参考数量を許容損失額、建値・損切り差、ATR、必要保証金、維持率、既存建玉、集中、総レバレッジ、流動性の各上限から決定し、最小数量を採用する
- 現物、信用買い、信用売りを別系列でバックテストし、手数料、スプレッド、信用金利、貸株料、借株コスト、逆日歩、為替、配当相当額等を分離表示する
- 信用取引可否、在庫、費用、返済期限、保証金等の必須情報が不足する場合、信用売りを約定させず、下落シグナルを利益計上しない
- 維持率低下、必要保証金不足、返済期限、上方ギャップ、踏み上げ、買い戻し不能、強制決済を保守的に処理する
- 流動性不足、信用残偏り、決算直前、高ボラ、データ不足、リスクリワード不足、集中、総レバレッジ超過を警告またはハード禁止とし、理由コードを監査保存する
- レバレッジ・インバースETFの信用取引では、内部レバレッジ重複、高ボラ、長期乖離、ギャップ、強制決済を警告し、通常ETFよりリスクを少なくとも1段階引き上げる
- 信用費用または適格性履歴がない値を0または取引可能として補完せず、版付き代理モデルによる研究結果と実データ結果を分離する
- 信用取引を含め、証券会社の認証情報・発注API・注文送信を実装せず、最終判断と注文が利用者にあることを表示する
- 利用者が複数のティッカーを指定でき、各入力を`market + exchange + symbol`から一意の`asset_id`へ解決する
- 無効、曖昧、重複、対象外ティッカーを理由付きで拒否し、指定集合外の銘柄を分析・仮想注文へ暗黙追加しない
- 指定集合の名称、版、作成日時、適用開始、構成ハッシュを保存し、追加・削除を新しい版として扱う
- 分析は口座残高を変更せず、利用者が明示開始したシミュレーションだけが凍結済み分析スナップショットを使用する
- 指定集合専用の短期・中期各250万円口座を通常口座、デモ、全銘柄評価から分離する
- 指定集合全体とティッカー別の取引、損益、費用、最大ドローダウン、約定不能、ベンチマークを確認できる
- 集合変更後も既存分析、取引、口座残高、監査記録を変更せず、指定集合外の新規建てを拒否する
- 正式な未見検証では集合を開始前に凍結し、結果を見て変更した集合による同一検証期間の再利用を拒否する
- 遡及選択、現存銘柄だけの選択、混合市場・通貨、USD/JPY欠損について品質警告または評価保留を行う
- 判断、見送り、約定不能、仮想取引結果を当初の判断カードと入力ハッシュへ関連付け、結果判明後も元の判断を変更しない
- 決済済み仮想取引は長短方向、為替、費用、配当等を照合し、完全性確認済みの保有期間価格だけからMFE、MAE、保守的ドローダウン、同期間ベンチマーク差を再現できる
- 見送り・約定不能の後続価格は反実仮想観測として成績から除外し、欠損を0損益・0変動として扱わない
- ナレッジで観測、仮説、検証中、検証済み、結論不十分、反証、廃止を区別し、賛成・反対証拠と適用範囲を表示する
- 3検証窓・30決済未満を成績判定せず、十分な標本でも独立した未見検証、費用、ベンチマーク、信頼区間、最大ドローダウン、頑健性を確認する
- 仮想成績やLLM提案から稼働中ルールを自動変更せず、差分・検証証拠・利用者承認を持つ新戦略版としてだけ昇格する
- 旧ナレッジ、反証、旧戦略版、過去シミュレーションを上書き・削除しない
- 自動実行はMarket Signal Lab内の仮想口座だけに限定し、証券会社への注文・予約・画面操作を発生させない

## 投資判断
- 根拠と反対材料を併記
- エントリー、利益確定、損切り、無効条件を区別
- 過去類似件数と検証結果を表示
- 自動発注しない
- 最終判断が利用者にあることを表示
