# 25 シミュレーション振り返り・ナレッジ更新仕様

- 確定日: 2026-08-25
- 対象: 市場の兆候検出、前向き仮想口座、取引後レビュー、検証可能なナレッジ
- 位置づけ: 仮想取引の結果から知見を蓄積する機能の正本

テーマ、関連ETF、説明変数、テーマ強度、流動性、日次ランキングの詳細は[27 注目テーマ・セクターETF仕様](27_theme_sector_etf.md)を正本とする。

## 1. 目的

金価格上昇のように、金利、為替、資金フロー、価格ブレイク、ニュース等の複数の兆候が重なる局面を、その時点で利用可能だった情報だけから検出する。検出結果を短期・中期の仮想口座で取引し、成功、失敗、見送り、約定不能を後から同じ基準で振り返る。

振り返り結果はシステム内のナレッジとして追記し、似た局面の説明、反対材料、検証課題に再利用する。ただし、仮想成績から稼働中のスコアや売買ルールを無審査で自己変更しない。

証券会社への発注、自動注文、注文画面操作は対象外である。「自動取引」はMarket Signal Lab内の仮想口座だけを意味する。

## 2. 対象

- 日本株、米国株、日本ETF、米国ETF
- 現物、将来の信用買い・信用売り・自動選択
- 全銘柄、利用者指定ティッカー集合、テーマ・資産クラス別の研究系列
- 短期・中期各250万円の独立仮想口座
- 金、半導体、防衛、AIインフラ、ロボティクス、電力・電化、銅、銀、宇宙、サイバーセキュリティ、トークン化、高配当・キャッシュフロー等のテーマ研究系列
- 各テーマETFに必要な米国先行資産、商品、為替、金利、ボラティリティ、資金フロー、イベント等の説明変数

金、原油、金利、為替等は原則として説明変数またはETF原資産として扱う。先物、FX、コモディティ現物の仮想売買を暗黙に追加しない。

## 3. 時点整合した兆候検出と仮想取引

1. 判断時刻までに利用可能だった価格、指数、為替、金利、ファンドフロー、財務、ニュース・イベントだけを凍結する。
2. データ鮮度、欠損、ライセンス、取引可能性、流動性の品質ゲートを通す。
3. Pythonが決定論的に兆候、反対材料、強度、無効条件、利益確定、損切り、参考数量を計算する。
4. 兆候を`watch`、`forming`、`confirmed`、`overheated`、`invalidated`等の版付き状態で保存する。状態名は実装時に列挙型として確定する。
5. ルール条件を満たした場合だけ、判断後の次取引可能セッションから仮想口座で注文・約定を評価する。
6. 候補なし、データ不足、取引禁止、約定不能も結果として保存する。
7. 実現後に、当初の根拠と反対材料を変更せず、結果を別イベントとして追記する。

最新ニュースを12週遅れ価格へ混ぜない。過去検証では当時のニュース、現在判断では同時点の現在価格を必要とする。

## 4. 取引後レビュー

各判断カードまたは見送りについて、少なくとも次を記録する。

- 判断時点、入力ハッシュ、データ時点、戦略・ルール・費用・約定版
- 当初の兆候、根拠、反対材料、無効条件、品質警告
- 仮想注文、約定、部分約定、約定不能、決済理由
- 手数料・スプレッド・スリッページ・為替・信用固有費用控除後の損益
- 最大有利変動、最大不利変動、保有期間、最大ドローダウン
- 同期間ベンチマークとの差、相場局面、業種、流動性、ボラティリティ
- 想定どおりだった要因、外れた要因、未観測要因、後から判明した情報
- 「取引しなかった場合」を含む見送り結果。ただし結果を見て選んだ反実仮想を成績へ混ぜない

LLMは構造化済みレビューの要約と論点整理に利用できるが、損益、価格、指標、統計を計算しない。

## 5. ナレッジのライフサイクル

```text
不変の判断・市場観測
  -> 結果レビュー
  -> パターン仮説
  -> 独立した未見期間で検証
  -> 採用候補／結論不十分／反証／廃止
  -> 利用者承認後だけ新しい戦略版へ昇格
```

- `observation`: 1件の判断、見送り、市場局面、取引結果という観測事実
- `hypothesis`: 複数観測から得た未検証の仮説
- `under_validation`: 凍結済みルールで未見検証中
- `validated`: 所定の品質ゲートを通過した知見。将来利益の保証ではない
- `inconclusive`: 標本不足または信頼区間が広く結論不能
- `refuted`: 独立検証で支持されなかった仮説
- `retired`: データ、制度、市場構造またはルール変更で利用停止した知見

過去の状態をUPDATEで書き換えず、状態遷移、根拠、反証、承認を新しい版またはイベントとして追記する。相反する知見を削除せず、対象期間・局面・データ版とともに併記する。

## 6. ルール昇格の品質ゲート

- 単一取引、単一銘柄、単一相場局面、デモ結果だけからルールを昇格しない。
- 少なくとも既存基準の3検証窓・30決済未満は成績判定しない。これは必要条件であり、十分条件ではない。
- 学習、未見検証、前向き期間を分離し、同じ検証期間を変更後ルールの選択に再利用しない。
- 費用控除後成績、ベンチマーク、信頼区間、最大ドローダウン、局面別安定性、感度を確認する。
- 多重比較、選択バイアス、サバイバーシップバイアス、ニュースの先読みを監査する。
- 新ルールは既存ルールを上書きせず、新しい戦略版として登録する。
- 自動提案は許可するが、自動承認・自動配備はしない。利用者が差分と検証証拠を確認して承認する。
- 承認後も前向きシャドー運用を行い、実投資支援品質を自動的に引き上げない。

## 7. DB設計への要求

実装時は少なくとも次の概念を追加する。正式なテーブル名はマイグレーション設計時に確定する。

- `simulation_reviews`: 判断カード、口座イベント、結果、ベンチマーク、レビュー版を結ぶ追記型レビュー
- `knowledge_items`: 状態、対象資産・局面、仮説本文、構造化条件、適用範囲、作成元、版
- `knowledge_evidence_links`: 観測、取引、見送り、検証窓、分析結果、ニュース参照を賛成・反対証拠として関連付ける
- `strategy_change_proposals`: 現行版、新版候補、変更差分、検証証拠、承認状態、承認者、承認時刻
- `knowledge_events`: 作成、検証開始、採用候補、反証、廃止、承認を追記する監査イベント

入力ハッシュ、ルールハッシュ、データ版、利用可能時刻、実行日時、コード版を保存する。ニュース本文は利用規約と保存権限を確認し、権利がない場合は識別子、URL、配信元、時刻、許可された要約・構造化特徴だけを保持する。

## 8. UI

- 分析画面: 現在の兆候、状態遷移、根拠、反対材料、データ時点、品質警告
- 仮想口座画面: 兆候から生じた判断、注文、約定、決済、見送りの時系列
- 振り返り画面: 予想と結果の差、費用控除後損益、ベンチマーク、局面別集計
- ナレッジ画面: 観測・仮説・検証済み・反証・廃止の区別、証拠、反対証拠、適用範囲、版
- ルール変更画面: 現行版との差、未見検証、リスク、承認・却下。初期実装は承認記録のみで自動配備しない

## 9. 金上昇兆候の例

金ETFを対象にする場合、金現物・連動指数、USD/JPY、ドル指数、米名目・実質金利、VIX、ETF資金フロー、出来高、NAV乖離、関連ニュースを取得可能な範囲で時点整合させる。

「金利低下」「ドル安」「資金流入」「価格上抜け」等を個別特徴として保存し、同時成立を兆候候補にする。ただし、この組み合わせを今回の上昇結果を見た後に同じ期間へ最適化して成績としない。過去時点再現と、その後の未見・前向き期間で検証してからナレッジ状態を更新する。

同じ原則を半導体、AIインフラ、防衛、銀、銅、宇宙等へ適用するが、テーマごとの説明変数とモデルを分離する。基準Tier、日次ランキング、Tier変更提案を混在させず、テーマ構成や重みの変更を新しい版として将来日から適用する。

## 10. 実装境界

既存の共通OHLC口座、追記台帳、判断カード、未見検証、区分評価、監査を再利用する。J-Quants Freeの遅延研究結果を正式な現在判断ナレッジへ昇格しない。完了状態と残タスクは`docs/22_current_priority_todo.md`を正本とする。

KN-P0では、凍結済み判断を入力として保持する`simulation-review-v1`と追記専用`simulation_reviews`を実装した。現物・信用買いは上方向、信用売りは下方向を有利変動として、口座通貨換算後の費用控除前後損益、MFE、MAE、保守的な保有中ドローダウン、同期間ベンチマーク差を決定論的に計算する。日足等の区間価格は約定後かつ決済前に完結し、経路完全性ハッシュを持つ場合だけMFE／MAEへ使う。見送り・約定不能の後続価格は反実仮想観測として保存できるが、口座成績へ含めない。根拠、反対材料、後から観測された要因はコードと入力ハッシュで分類し、元判断を更新しない。

現行サービスは`synthetic_research`と`delayed_historical`だけを受け入れる。既存口座・バックテストからのレビュー自動生成、画面、ナレッジ状態遷移、集計、LLM要約、`current_market`は後続タスクであり、KN-P0完了を理由に有効化しない。
