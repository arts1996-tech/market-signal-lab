# 23 信用取引モード仕様

- 追加日: 2026-08-24
- 対象: 日本株、米国株、日本ETF、米国ETF
- 位置づけ: 信用取引の製品要件、データ境界、分析、仮想口座、バックテスト、リスク管理の正本

## 1. 目的と適用範囲

Market Signal Labへ、現物に加えて信用買い・信用売りを判断材料および仮想評価の対象として追加する。証券会社への接続、自動発注、注文代行は行わない。システムは候補、条件、費用、証拠金、反対材料、禁止理由を提示し、最終判断と注文は利用者が手動で行う。

取引モードは次の4種類とする。

- `cash`: 現物
- `margin_long`: 信用買い
- `margin_short`: 信用売り
- `auto_select`: 利用可能なモードを同じ判断時点で比較し、最も条件に合う仮想シナリオを選ぶ

`auto_select`は注文方式ではない。候補となったモードと、採用しなかった各モードの理由を表示する。必要情報が不足する場合は現物へ暗黙フォールバックせず、`insufficient_data`または`not_eligible`とする。

## 2. 市場ごとの正規化

- 日本資産では、制度信用／一般信用、貸借銘柄、信用買い・信用売り可否、返済期限等を取得元の定義のまま保存する。
- 米国資産では、margin eligibility、short availability、borrow availability、borrow fee、maintenance requirement等を共通項目へ正規化する。
- 日本固有の制度を米国資産へ推測適用せず、該当しない値はNULLとする。
- ETFも同じ取引モードを持てるが、ETF固有の流動性、NAV、内部レバレッジ、インバース区分を追加評価する。
- 取得元、対象証券会社・市場、適用開始／終了時刻、取得時刻、利用可能時刻、通貨、品質状態を必ず保持する。取引可否や費用は時点で変わるため、現在値で過去を上書きしない。
- SBI証券、楽天証券等の国内証券会社条件は`broker_scope`を分け、制度信用、一般信用、デイトレ信用、在庫、金利、貸株料、返済期限、保証金条件を同一条件として混在させない。テーマETF固有要件は`docs/27_theme_sector_etf.md`を参照する。

## 3. 信用取引固有データ

取得可能な範囲で次を管理する。値がない場合は推測せずNULLとし、必須項目の欠損は候補抑制または禁止理由にする。

- 信用買い可否、信用売り可否
- 制度信用／一般信用
- 貸借銘柄かどうか
- 信用買い残、信用売り残、貸借倍率
- 逆日歩、借株コスト
- 信用金利、貸株料
- 返済期限
- 必要保証金、最低保証金率、維持率
- 強制決済条件・リスク
- short availabilityまたは在庫状態（取得可能な場合）
- 規制、取引停止、増担保、空売り価格規制等（取得可能な場合）

残高、倍率、費用、取引可否には`effective_at`、`available_at`、`fetched_at`を持たせる。公表後に利用可能となった情報だけを分析へ渡し、後日判明した逆日歩等を過去判断へ先読みしない。

## 4. 信用買い分析

信用買い候補は、少なくとも次を決定論的に評価する。

- 上昇トレンドと市場環境
- 出来高増加、売買代金、流動性
- 支持線、ATR、ギャップリスク
- 信用買い残の過熱と貸借倍率
- 決算・重要イベントまでの営業日数
- 必要保証金、維持率、強制決済余裕
- 損切りまでの想定損失
- 保有予定日数に対応する信用金利と諸費用

信用買い残の極端な増加、維持率不足、決算直前、高ボラティリティ、必要データ不足では、現物より信用買いのリスク評価を引き上げる。

## 5. 信用売り分析

信用売り候補は、少なくとも次を決定論的に評価する。

- 下落トレンド、戻り売り候補、抵抗線
- 出来高、売買代金、流動性
- 市場環境とギャップ上昇リスク
- 信用売り残、貸借倍率、踏み上げリスク
- 逆日歩、借株コスト、貸株料と利用可能在庫
- 決算・重要イベントまでの営業日数
- 必要保証金、維持率、強制決済余裕

信用売り可否、利用可能在庫、費用、返済期限のいずれかが必要水準で確認できない場合、仮想口座へ信用売り利益を計上しない。損失は理論上限定されないため、上方ギャップ、ストップ高、買い戻し不能を保守的に扱う。

## 6. レバレッジ・インバースETF

レバレッジETFまたはインバースETFを信用取引する場合は、通常ETFよりリスクレベルを少なくとも1段階引き上げ、次を明示警告する。

- ETF内部レバレッジと信用取引によるレバレッジの重複
- 高ボラティリティとATR拡大
- 日次連動設計による長期保有時の指数との乖離・複利効果
- 窓開けと流動性低下
- 維持率低下と強制決済

内部レバレッジ倍率を取得できない場合は推測しない。レバレッジ・インバース区分だけ確認できる場合は、保守的な上限を適用して`human_review_required=true`とする。

## 7. ポジションサイズと口座制約

短期・中期各250万円の既存口座を維持し、新しい別資金は作らない。現物、信用買い、信用売りの建玉と拘束額を同じ口座内で分離記録し、口座間の資金移動は行わない。

基本数量は、次のうち最小の数量とする。

```text
risk_budget = account_equity * per_trade_risk_rate
risk_per_unit = abs(entry_price - stop_price) + estimated_exit_cost_per_unit
risk_limited_quantity = floor(risk_budget / risk_per_unit)
final_quantity = min(
  risk_limited_quantity,
  margin_capacity_quantity,
  liquidity_limited_quantity,
  concentration_limited_quantity,
  leverage_limited_quantity
)
```

計算には建値、損切り価格、ATR、1取引の許容損失率、必要保証金、維持率、他の建玉、同一業種集中、保有相関、総レバレッジ、返済期限までの費用を含める。数量は市場の売買単位に丸め、0以下なら取引を見送る。

- `gross_leverage = gross_position_notional / account_equity`
- 信用建玉の必要保証金を利用可能余力から拘束する。
- 評価損、費用、保証金率変更を反映した維持率を日次で再計算する。
- 維持率が警戒閾値を下回る場合は新規信用建てを禁止し、強制決済リスクを表示する。
- 実際の証券会社規則が取得できない場合は、仮定版を明示した保守的モデルに限定し、実口座の余力として表示しない。

## 8. バックテストと仮想口座

現物、信用買い、信用売りを別系列で評価し、`auto_select`はそれらを選択した合成系列として別に評価する。モード別に取引数、損益、最大ドローダウン、費用、強制決済、約定不能、比較ベンチマークを表示する。

可能な限り次を時点整合的に反映する。

- 売買手数料、スプレッド、スリッページ
- 信用金利、貸株料、借株コスト、逆日歩
- 為替コスト
- 配当・分配金と信用売り側の配当相当額
- 返済期限、保証金、維持率、強制決済
- 部分約定、取引停止、値幅制限、買い戻し不能

費用または取引可否の履歴を取得できない期間は、ゼロとして扱わない。保守的な版付き代理値を使った研究結果と、実データ結果を分離する。信用売りの本番評価は、最低限、売建可否、借株・逆日歩等の費用、返済期限、保証金、配当相当額、買い戻し制約を時点整合的に扱えるまで完成としない。

## 9. リスク抑制・禁止条件

次の条件では信用候補を抑制または禁止できるようにする。閾値、判定版、理由コードを保存する。

- 流動性不足、約定不能
- 信用残の極端な偏り、踏み上げリスク
- 決算・重要イベント直前
- 高ボラティリティ、ギャップリスク
- 必須データ不足または古いデータ
- リスクリワード不足
- 維持率低下、必要保証金不足、返済期限接近
- 1銘柄、同一業種、相関資産への集中
- 総レバレッジ上限超過
- レバレッジ・インバースETFと信用取引の組み合わせによる過大リスク

ハード禁止と警告を分ける。ハード禁止時は理由を表示して仮想注文を生成しない。警告時も`human_review_required=true`とする。

## 10. 監査・セキュリティ

- 判断カード、仮想注文、約定、日次評価に取引モード、売買方向、適格性、費用版、保証金版、リスク規則版を保存する。
- `auto_select`では比較した全モードの入力ハッシュ、評価結果、却下理由を保存する。
- 証券会社の認証情報、口座番号、発注API、ブラウザ自動操作を実装・保存しない。
- 外部入力とLLM出力から取引モード、数量、保証金、費用を直接確定させず、Python境界で列挙値、型、範囲、鮮度を再検証する。
- 自動発注、注文予約、証券会社への送信は信用取引を含め禁止する。
- 証券会社別条件の取得は公開情報、利用者の明示入力、または承認済みproviderに限定し、ログイン情報やブラウザ自動取得を使用しない。

## 11. 段階的な実装順序

1. **完了（MT-P0）**: `cash`、`margin_long`、`margin_short`、`auto_select`、日米の制度差、適格性、在庫、費用、保証金、返済期限、規制、時点・品質を表す不変型とprovider境界を追加した。欠損、未来取得、期限外、古い、利用不能、合成研究データは信用取引可能へ変換せず、`not_eligible`と`insufficient_data`を分離する。`auto_select`の戦略比較、実provider、DB、分析、約定は後続MT-Pで接続する。
2. **完了（MT-P1）**: 適格性、信用区分、在庫・規制、信用残・貸借倍率・逆日歩、金利・貸株料・借株費用、保証金、返済期限を`asset_trading_capabilities`、`margin_market_snapshots`、`financing_term_snapshots`へ分離して追記保存する。provider記録の再取得時刻を版として保持し、同一入力を冪等化する。判断時点までに有効・利用可能・取得済みの同一source・broker系列だけを読み、NULLをゼロや取引可能へ変換しない。実provider、分析カード、仮想約定はまだ接続しない。
3. **完了（MT-P2）**: 信用買い・信用売りの不変な分析入力と判断カードを追加し、MT-P0の適格性を先に検証する。上昇／下落トレンド、出来高・売買代金、支持・抵抗、ATR・ギャップ、市場環境、信用残変化・貸借倍率、決算等までの日数、維持率余裕、リスクリワード、費用、返済期限、provider規制を版付き理由コードで警告またはハード禁止にする。レバレッジ・インバースETFは内部倍率を推測せず、通常ETFよりリスクを少なくとも1段階引き上げる。合成入力による分析カードまでとし、仮想注文、口座変更、実provider、画面は接続しない。
4. **完了（MT-P3）**: 合成研究用の共通OHLC状態遷移コアへ、信用買い・信用売り、許容損失・保証金余力・流動性・銘柄／業種／相関集中・総レバレッジの最小数量、出来高上限による部分約定、最低保証金、日次信用費用、時点付き条件改定、返済期限、窓開け、同日利確／損切りの保守的順序、維持率割れ後の翌営業日強制決済を接続した。維持率警戒中または強制決済待ちの口座では新規建てを禁止する。信用売りの上方ギャップ・踏み上げと、値幅制限・取引停止等による通常決済・買い戻しの繰延も保持し、全イベントへ`real_order_sent=false`と入力版を残す。MT-P2判断カードとproviderスナップショットの同一銘柄・モード・判断時点・provider記録を再検証する。実provider、DB保存、既存現物口座、配当相当額、企業行動、画面、モード別成績系列は未接続であり、MT-P4で統合する。
5. 現物、信用買い、信用売り、`auto_select`を別系列でバックテストする。
6. MT-P2のレバレッジ・インバースETF追加リスク制御を、保存済み判断カードの画面表示へ接続する。
7. 公式条件とユーザー承認済みデータソースを接続し、実データ品質ゲートを検証する。

既存の買いのみ経路は、信用取引が各完了条件を満たすまで現物モードとして維持する。段階途中で下落シグナルを信用売り利益へ変換しない。
