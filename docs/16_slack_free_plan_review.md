# 16 Slack無料プランでの運用可否評価

## この文書の位置づけ
本文書は、`docs/06_slack_integration.md` の仕様がSlack無料プラン(Free)の制約内で運用可能かを検証した外部レビューである。
要件を変更するものではなく、既存仕様への補足である。フェーズ6「Slack連携」着手時に参照すること。

## 1. Slack無料プランの制限（確認時点）
- メッセージ・ファイルの閲覧履歴は直近90日まで（1年経過分は完全削除）
- 連携できる外部アプリ（カスタムアプリ含む）は最大10個
- ファイルストレージは5GBまで
- ハドルミーティング（音声・ビデオ通話）は1対1のみ
- ユーザー数に上限はなく、Bot自体の稼働・API呼び出し回数に対する課金は無料プランでも発生しない

## 2. docs/06仕様との照合

### 2.1 問題なく無料プラン内でクリアできる項目
- Bolt for Python + Socket Modeによる常時接続
- `/market`、`/analyze SYMBOL` 等のスラッシュコマンド
- DM・メンション・スレッド内対話
- Block Kitによる分析結果表示
- 定期投稿（市場オープン前レポート等）

これらはいずれもSlack APIの機能であり、ワークスペースのプラン（Free/Pro等）による制限を受けない。API呼び出し回数そのものに対する課金も無料プランで発生しない。

### 2.2 アプリ連携数について
本システムで必要なカスタムアプリは1つ（このBotのみ）であり、「アプリ連携10個まで」という無料プランの制限に対して十分な余裕がある。

### 2.3 利用者数について
利用者は1人（個人利用）を想定しているため、複数人利用時に問題となりうるプラン制限（通話人数制限等）は本システムには影響しない。

## 3. 注意すべき点

### 3.1 メッセージ履歴90日制限
Botが過去に投稿した分析結果・利用者とのやり取りは、Slack上では90日を過ぎると閲覧できなくなる。
ただし、docs/07で`slack_conversations`テーブルへ会話履歴をPostgreSQL側に保存する設計になっているため、記録の実体はDB側に残る。Slack上のUIで長期間のやり取りを直接スクロールして見返したい場合にのみ制約となる。

### 3.2 ファイルストレージ5GB制限
Block Kitによるテキスト・カード表示のみであれば問題にならない。将来的にチャート画像やPDFレポートをSlackへ直接アップロードする機能を追加する場合、蓄積して5GBに近づく可能性がある。

**推奨対応**:
- チャート等の画像はStreamlitダッシュボード（Raspberry Pi上）側で表示し、Slackには画像を直接アップロードせずリンクのみを送る
- どうしても画像添付が必要な場合は、古いファイルを定期的に削除する運用（またはジョブ）を設ける

## 4. 結論
現状のdocs/06の設計は、Slack無料プランの範囲で問題なく運用可能である。有料プランへの移行を検討すべきタイミングは、以下のいずれかが実際に運用上の支障として顕在化した場合で十分である。
- Slack上で90日より前の分析結果・やり取りを直接見返したい場面が頻発する
- Botがアップロードするファイルが5GBに近づく

現時点（フェーズ6着手前）では、無料プランのままで仕様上の問題はない。
