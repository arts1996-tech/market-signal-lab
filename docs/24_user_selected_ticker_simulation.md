# 24 利用者指定ティッカー分析・仮想口座仕様

- 追加日: 2026-08-25
- 対象: 日本株、米国株、日本ETF、米国ETF
- 位置づけ: 利用者が複数のティッカーを指定する分析対象集合と、その集合に限定したシミュレーション／仮想口座の正本

## 1. 目的

利用者が関心のあるティッカーを複数明示指定し、その集合だけを対象に分析と仮想評価を行えるようにする。システムが指定外の銘柄を暗黙追加したり、ランキング上位銘柄へ自動置換したりしない。

分析とシミュレーションは画面、実行記録、責務を分離する。ただし価格検証、指標計算、シグナル生成、OHLC約定、口座計算は既存の共通エンジンを再利用し、同じ計算を別実装しない。

```text
利用者指定ティッカー集合
  -> ティッカー別分析
  -> 凍結した分析スナップショット
  -> 指定集合限定シミュレーション
  -> 独立した仮想口座・監査記録
```

## 2. ティッカー指定

- 利用者は1件以上のティッカーを指定できる。
- ティッカーは`market + exchange + symbol`から既存`asset_id`へ解決し、表示名だけで識別しない。
- 重複は同じ`asset_id`へ正規化し、無効、未登録、対象外資産、曖昧なティッカーは理由付きで拒否する。
- 日本株、米国株、日本ETF、米国ETFを同じ選択集合へ含められるが、市場セッション、通貨、売買単位、為替データを分離処理する。
- 選択集合には名称、作成日時、作成者、版、状態、適用開始日時を持たせる。
- ティッカーの追加・削除・並べ替えは新しい版として保存し、過去の分析、シミュレーション、仮想口座を変更しない。
- 無効化した集合も監査・再現のため削除せず、後続実行の対象外にする。

初期実装では利用者が明示指定した集合だけを使う。ニュース、LLM、スコア、ランキングによる自動追加は行わない。

## 3. 分析とシミュレーションの分離

### 分析

分析は売買と口座残高を変更しない。ティッカーごとに次を表示・保存する。

- データ時点、取得元、価格基準、連続営業日数、品質警告
- テクニカル、財務、ETF固有情報、市場・日米波及情報
- 現物、信用買い、信用売りの適格性と不足データ
- エントリー、利益確定、損切り、無効条件の候補
- 根拠、反対材料、人手確認要否
- 分析ルール版、入力ハッシュ、`analysis_run_id`

分析結果はシミュレーション開始時に凍結し、後から再分析しても既存のシミュレーション入力を置換しない。

### シミュレーション

シミュレーションは、指定集合の版、凍結済み分析スナップショット、戦略版、期間、費用、口座条件を入力として仮想約定する。分析画面から直接口座残高を変更せず、利用者がシミュレーション開始を明示した場合だけ独立実行する。

## 4. シミュレーション方式

初期対象は、指定された複数ティッカーを投資可能集合とする`selected_universe_portfolio`方式とする。ティッカー別成績も同じ実行から分離集計する。

- 短期・中期はそれぞれ独立し、初期資金は既存仕様と同じ各250万円（JPY）を既定値とする。
- 通常の継続仮想口座、デモ口座、全銘柄バックテストと資金・成績・監査系列を混在させない。
- 選択集合外の銘柄は、シグナルがあっても仮想注文を生成しない。
- 同じ資金で複数ティッカーを評価し、資金拘束、同時保有上限、1銘柄上限、業種・相関集中、流動性を既存口座と同じ共通エンジンで処理する。
- 現物、信用買い、信用売り、自動選択は`docs/23_margin_trading.md`の品質ゲートに従う。信用機能完成前は現物買いだけを有効にする。
- USD資産を含む場合は取引時・評価時の時点整合USD/JPYを必須とし、欠損時は約定・評価を保留する。
- 結果には集合全体とティッカー別の取引数、損益、費用、最大ドローダウン、勝率・区間、約定不能、ベンチマーク比較を表示する。

将来、ティッカーごとに独立資金を持つ比較方式を追加する場合は、`independent_per_asset`として別ルール版・別実行系列にし、ポートフォリオ結果と混在させない。

## 5. 継続仮想口座

過去期間の一回限りのシミュレーションと、毎営業日追記する継続仮想口座を分ける。

- 過去シミュレーションは`backtest_run`として不変の期間・入力で再現する。
- 継続仮想口座は、指定集合の固定版を`allowed_universe`として持つ独立口座にする。
- 継続中に集合を変更する場合、既存口座の過去状態を書き換えず、新しい口座版または将来適用の集合版を開始する。
- 削除されたティッカーの既存保有は暗黙決済せず、変更時に「新規建て禁止」「計画決済」「新口座へ移行」のいずれかを明示する。初期実装では新規建て禁止とし、既存ルールで決済まで追跡する。
- 遅延価格の`delayed_historical`と現在価格の`current_market`を分離する。J-Quants Freeの間は正式な現在判断・前向き成績として扱わない。

## 6. 選択バイアスと検証

利用者指定であっても、値上がりを知った後に銘柄を選ぶとバックテスト成績が過大になる。次を必須とする。

- 指定集合の版、構成銘柄、作成時刻、適用開始時刻、選定理由を保存する。
- 正式な未見検証では、集合を検証期間開始前に凍結する。
- 検証期間を見た後に集合を変更した場合、同じ検証期間を新しい集合版の正式評価へ再利用しない。
- 過去情報を見て作成した集合を過去へ遡及適用する場合は、`retrospective_user_selected`と表示し、前向き成績や予測能力の証明に使わない。
- 現存銘柄だけを選んだ集合にはサバイバーシップバイアス警告を表示する。
- 連続営業日、短期80営業日、中期140営業日等の既存品質ゲートを、銘柄数が少ないことを理由に緩和しない。

## 7. DB・監査候補

実装時には既存テーブルを生かし、少なくとも次を保持する。

- `user_asset_selections`: 名称、版、作成日時、適用開始、状態、選定理由、構成ハッシュ
- `user_asset_selection_items`: selection_id、asset_id、追加日時、表示順、状態
- `analysis_runs`: selection_id、selection_version、asset_id、as_of、入力ハッシュ、分析版
- `backtest_runs`: `scope=selected_universe`、selection_id、selection_version、分析スナップショット集合ハッシュ
- `virtual_accounts`: `account_scope=selected_universe`、allowed_selection_id、allowed_selection_version

同じ集合版、分析入力、戦略版、期間、口座条件の再実行は冪等に扱う。構成変更や異なる入力による既存結果の上書きを拒否する。

## 8. UI

画面は次の3領域へ分ける。

1. `指定ティッカー管理`: 追加、削除、新版作成、無効化、入力エラー、構成ハッシュ
2. `指定ティッカー分析`: ティッカー別分析、品質警告、分析スナップショット作成
3. `指定集合シミュレーション`: 期間、短期／中期、取引モード、口座条件の確認と、独立した結果表示

分析結果を表示しただけではシミュレーションを開始しない。開始前に対象集合版、データ時点、遅延、戦略版、費用、初期資金、品質警告を確認できるようにする。

実装タスクは重複させず、`指定ティッカー管理`と`指定ティッカー分析`を`LITE-P1`へ、`指定集合シミュレーション`と継続口座の状態・拒否理由・履歴を`LITE-P4`へ統合する。LiteはUIからDBを直接更新せず、利用者の明示操作を既存サービス層へ渡す。指定集合の毎営業日実行、通常口座・重い分析との排他、同日再試行の冪等性は`NOW-P2-8`で実装済みとし、追記型の明示有効化イベントがない集合版は処理しない。Mac／Raspberry Piの実行主体判定は`NOW-P2-11`へ集約する。

## 9. セキュリティと禁止事項

- ティッカー入力を許可文字、長さ、market／exchange、既存資産との完全一致で検証する。
- 利用者入力から任意SQL、任意コード、外部URL、証券会社操作を実行しない。
- 指定集合は分析・仮想評価の範囲指定であり、証券会社への注文リストではない。
- 自動売買、自動発注、注文予約、ブラウザ自動入力を実装しない。
- LLMにティッカー集合を無断変更させず、提案が必要な場合も別候補として表示し、利用者の明示追加を必要とする。

## 10. 段階的な実装順序

1. **完了（ST-P0）**: 選択集合入力、`market + exchange + symbol`の完全一致解決、無効・曖昧・重複の拒否、構成ハッシュを追加した。DB保存、画面、分析、シミュレーションはまだ開始しない。
2. **完了（ST-P1）**: 集合の安定キー、版、状態、作成者、適用開始、理由、構成ハッシュと項目をDBへ追記保存する。構成変更は別版とし、Mac開発DBでupgrade/downgrade往復と初版→新版の保存を確認した。分析、シミュレーション、画面はまだ開始しない。
3. **完了（ST-P2）**: 選択集合版と既存の全銘柄分析runを入力に、選択資産だけの不変分析スナップショットを作成する。品質ゲートで元分析から除外された資産も不足理由を保存し、口座・注文・取引イベントは変更しない。同一入力は再利用する。画面とシミュレーションはまだ開始しない。
4. **完了（ST-P3）**: 凍結済み分析スナップショットの選択資産だけを対象に、短期・中期それぞれ初期2,500,000 JPYの`selected_universe_portfolio`過去シミュレーションを共通OHLCエンジンへ接続した。現物買いに限定し、選択外・品質不足・JPX/JPY以外は理由付きで保存して推測実行しない。既存の口座・デモ・全銘柄バックテストは更新しない。これは`retrospective_user_selected`研究であり、前向き成績や予測能力の根拠にしない。画面と継続口座はまだ開始しない。
5. **完了（ST-P4）**: 選択集合の作成・適用時刻と検証期間を照合して分類する。開始前に凍結済みなら`precommitted_unseen`、そうでなければ`retrospective_user_selected`とする。集合の新版が同じ期間を正式な未見検証として使うことを拒否する。既存の後ろ向きシミュレーションは正式検証へ昇格させない。
6. **完了（ST-P5）**: 指定集合の不変な行ID・版・構成ハッシュを`virtual_accounts`へ固定し、通常口座とは別名・別残高・別監査系列の短期・中期継続口座を追加した。集合外、非JPX/JPY、非現物買い、無効項目は新規建て入口で理由付き拒否する。集合変更は旧口座を更新せず新版の別口座を開始する。旧版口座は新規建てを停止し、価格追跡と既存ルールによる決済だけを継続するため、旧版の既存保有を暗黙決済しない。J-Quants Freeでは`delayed_historical`研究だけを許可し、画面・日次自動開始・Raspberry Pi配置は行わない。
7. 信用取引は`docs/23_margin_trading.md`のMT-P完了後に同じ集合へ追加する。
8. 現在価格ソースと前向き品質ゲートの完了後に`current_market`へ移行する。
