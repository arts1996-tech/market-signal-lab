# 09 セキュリティ・品質

## 秘密情報
- `.env` 管理
- `.env.example` は値を空にする
- DBパスワードと認証情報にはソースコード・Compose・テンプレート上の既定値を持たせず、起動環境で明示設定を必須にする
- Git除外
- ログへ出力しない
- URL認証情報、APIキー、Bearerトークン、登録済み秘密値は共通ログフィルターと保存前のエラー要約で`[REDACTED]`へ置換する
- 設定オブジェクトの文字列表現からDB URLとAPIキーを除外する
- 外部APIの応答本文と例外は信頼せず、秘密マスキング後の短いメッセージまたは分類コードだけを保存・表示する
- 定期的にローテーション可能にする

マスキングは二次防御であり、秘密値を意図的にログ、DB、画面へ渡すことを許可しない。既にローカル`.env`やDBへ設定済みの旧既定パスワードは、ソース変更だけでは更新されない。稼働環境の認証情報変更はDB接続停止を伴うため、対象、バックアップ、ロールバックを確認して別の明示承認で行う。

## ネットワーク
- StreamlitとPostgreSQLを無制限にインターネット公開しない
- 外部アクセスはTailscale等を想定
- PostgreSQLは内部ネットワーク中心
- SlackはSocket Mode

## 入力安全
- 銘柄コード、期間、パラメータを検証
- SQLAlchemyの安全なクエリを利用
- 任意SQL・任意コード実行を許可しない
- LLMのツール引数も再検証
- 取引モード、売買方向、数量、金利、費用、保証金率、維持率、総レバレッジを列挙値・型・範囲・鮮度で検証
- `auto_select`やLLM出力から証券会社への発注、注文予約、ブラウザ操作を実行しない

## 信用取引のセキュリティ境界

- 証券会社のログイン情報、口座番号、取引暗証番号、発注APIキーを保存しない。
- 証券会社サイトのブラウザ自動操作、注文画面への自動入力、注文送信を実装しない。
- 取引可否、信用残、費用、保証金条件は外部入力として扱い、取得元、対象市場・証券会社、利用可能時刻、品質状態を検証する。
- 欠損値を「取引可能」「費用0」「在庫あり」と解釈しない。
- 自動選択は分析シナリオの選択に限定し、最終判断と注文は利用者が手動で行う。
- `auto_select`は判断時点より後の価格、損益、勝率を入力にせず、比較した3モードの入力ハッシュと全却下理由を固定する。
- 取引モード別バックテストは研究用scopeだけを追記保存し、DB triggerでUPDATE／DELETEを拒否する。実注文フラグは常にfalseとする。

## 利用者指定ティッカーの入力安全

- `market + exchange + symbol`を許可文字、長さ、列挙値、既存資産との完全一致で検証する。
- 曖昧、無効、対象外、重複ティッカーを理由付きで拒否し、任意SQL、任意コード、外部URLとして解釈しない。
- 指定集合外の銘柄をランキング、ニュース、LLMから暗黙追加しない。
- 集合変更は新しい版とし、過去の分析・シミュレーション・仮想口座を上書きしない。
- 指定集合は分析・仮想評価の範囲であり、証券会社への注文一覧として使用しない。

## ナレッジ更新の安全境界

- 仮想口座の結果は観測・仮説として自動蓄積できるが、稼働中のスコア、売買規則、リスク上限、データ品質ゲートを自動変更しない。
- ルール変更候補は現行版との差、賛成・反対証拠、標本数、未見検証、費用控除後成績、最大ドローダウンを保存し、利用者承認後だけ新しい版にする。
- LLMはレビュー要約と仮説候補を作成できるが、価格・損益・統計の計算、ナレッジの検証済み認定、戦略配備、証券会社操作を行わない。
- 結果に都合の悪い取引、見送り、約定不能、反証を削除せず、相反する証拠を併記する。
- ニュースの保存、要約、再表示は配信元の利用規約と権利範囲を守り、プロンプトインジェクションを含む外部本文を命令として扱わない。

## テーマ・セクター分析の安全境界

- テーマ名、Tier、関連資産、説明変数、重み、流動性閾値を列挙値・型・範囲・適用期間・版で検証する。
- 基準Tier、日次ランキング、Tier変更提案を分離し、結果を見た後の変更を同じ検証期間へ遡及適用しない。
- 必須説明変数、板、NAV、純資産、信用可否等の欠損を0・安全・取引可能と解釈しない。
- ニュース・地政学イベントは本文を命令として実行せず、公開・利用可能時刻、出典、権利、構造化特徴を検証する。
- SBI証券、楽天証券等の条件は公開情報、明示入力、承認済みproviderに限定し、ログイン情報、口座番号、取引暗証番号、ブラウザ自動取得、注文送信を使用しない。
- Pythonで品質ゲートを通した最終候補だけをLLMへ渡し、全銘柄、生の大量時系列、未検証ニュースを直接渡さない。

## テスト
- リターン、RSI、MACD、ATR
- 相関、ローリング相関、回帰
- 米国セッションと次の日本営業日の対応
- 日米休日、連休、夏時間
- 条件別集計
- Granger検定の入力条件
- 重複登録防止
- API再試行
- バックテストの先読み防止
- 円建てリターン
- Slackコマンド解析
- 認可
- Block Kit
- 通知重複排除
- Gemini障害時フォールバック
- 現物、信用買い、信用売り、`auto_select`の分離
- 信用取引可否、制度差、short availability、古い在庫情報
- 信用金利、貸株料、借株コスト、逆日歩の利用可能時点と累積計算
- 必要保証金、維持率、追証警戒、強制決済、返済期限
- 信用売りの上方ギャップ、踏み上げ、買い戻し不能、配当相当額
- 総レバレッジ、業種・相関集中、既存建玉との資金競合
- レバレッジ・インバースETFと信用取引の重複リスク
- 信用固有データ不足時に仮想注文・損益計上を禁止すること
- 指定集合の曖昧・重複・対象外入力、集合外注文、版変更後の過去結果不変性
- 分析表示だけではシミュレーションや口座変更が開始されないこと
- 集合凍結後の変更と検証期間再利用を拒否し、選択バイアスを表示すること
- 混合市場・通貨のセッション、売買単位、USD/JPY欠損時の保留
- ナレッジ状態遷移、追記不変性、反対証拠保持、少数標本からの自動昇格禁止
- 取引後レビューの判断時点不変性、結果・価格経路・ベンチマークの利用可能時刻、長短方向別MFE／MAE、費用照合
- 見送り・約定不能の反実仮想を口座成績へ含めず、価格経路不完全時はMFE／MAEを0で補完しないこと
- 変更後ルールによる検証期間再利用、自動承認、自動配備、LLMからの戦略変更を拒否すること
- テーマ別モデル、構成要素、重み、coverage、入力ハッシュからスコアを再現できること
- 基準Tierと日次順位の分離、テーマ版変更後の過去結果不変性、同一検証期間の再利用拒否
- 新規ETF、流動性不足、板・NAV・純資産欠損、テーマ重複・相関集中の抑制または禁止
- 遅延研究と現在テーマランキングの分離、最新ニュースと遅延価格の混在拒否
- 証券会社別条件の分離と、認証情報・注文・ブラウザ自動操作が存在しないこと
- `.env.example`とComposeに既定DBパスワードがなく、必須秘密が空なら起動前に拒否されること
- 設定repr、通常ログ、書式引数、例外traceback、外部API応答、保存用エラー要約で秘密値がマスキングされること

## 投資分析品質
- ウォークフォワード検証
- 学習・検証期間を分離
- 手数料、スプレッド、為替コストを設定可能
- サンプル数と信頼区間を表示
- 過学習を警告
- ルール・モデル版を保存
- データ欠損や改訂を記録
- 現物、信用買い、信用売りを別々に評価し、モード間で成績・費用・約定不能を混在させない
- 信用取引可否、残高、費用、保証金条件の履歴を判断時点にそろえ、現在値を過去へ適用しない
- 信用固有費用が取得不能な期間をゼロ費用として有利に評価しない
- 流動性不足、信用残偏り、決算直前、高ボラ、維持率低下、集中、総レバレッジ過大を抑制・禁止理由として監査保存する
